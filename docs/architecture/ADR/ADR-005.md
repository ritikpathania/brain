# ADR-005: Command & Event Contract Refinements

## Context
RFC-001 defined a single large `CommandResult` enum to wrap all responses and raw `String` paths for event subscription topics.
During implementation of PR-003, we identified three scalability issues:
1. A single mega-enum for command responses forces all callers to match against unrelated command results, increasing coupling and reducing extensibility.
2. Async events are versioned and audited via `EventEnvelope`, but commands lack an envelope structure, making auditing, latency profiling, and replay testing difficult.
3. Raw string-based event subscription topics (`subscribe("topic", ...)`) introduce risk of spelling errors and make static lint checks impossible.

## Decision
Refine the system contracts:
1. **Generic Command Result:** Replace the mega-enum `CommandResult` with a generic Result alias `pub type CommandResult<T> = Result<T, BrainError>` where each command returns its own specific response type.
2. **Command Envelope:** Wrap commands in a metadata-rich `CommandEnvelope` containing an execution ID, version, timestamp, and command payload.
3. **Typed Event Topics:** Define a strongly-typed `EventTopic` enum to identify event streams instead of using raw strings.

## Consequences
- **Extensibility:** Downstream crates can define new commands and specific response structs without modifying a shared enum in `brain-events`.
- **Auditing:** Execution metrics, tracing IDs, and timestamps are consistently attached to all queries and commands.
- **Safety:** Event bus topic subscriptions are validated by the compiler via `EventTopic` enums.
