# ADR-001: Consolidation of UI into a Native Rust Binary

## Context
The current CLI architecture extracts `cli.js` (compiled React/Ink TUI) and `yoga.wasm` layout engine binaries to a temporary directory under `/tmp` at startup and executes them by spawning an external `bun` process. This introduces:
1. Significant startup latency (>200ms).
2. Packaging fragility (un-packing and spawning processes at runtime).
3. A strict local runtime dependency on Bun being installed on the user's PATH.
4. File permissions vulnerabilities if writing to `/tmp` is blocked by system policies.

## Decision
Replace the React/Ink TUI client with an in-process, thread-isolated TUI built directly using `ratatui` and `crossterm`. The TUI will run on a dedicated OS thread spawned by the main executable and communicate with the core services using the Command/Event bus abstractions.

## Consequences
- **Startup Latency:** Drops to <10ms.
- **Portability:** Brain distributes as a single, compiled, static executable (~10MB) with zero dependencies.
- **Reliability:** Eliminates temp directory extraction hacks and the external Bun JavaScript runtime dependency.
- **Usability:** Standard terminal resizing, input loops, and viewports are handled deterministically via Crossterm.
