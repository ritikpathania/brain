# RFC-006: Interactive Knowledge Exploration Environment

**Author:** Antigravity & USER  
**Date:** 2026-07-13  
**Status:** Approved / Frozen  
**Reference RFCs:** RFC-001 (Event Ingestion Platform), RFC-004 (Brain Terminal UX Specification)

---

## 1. Executive Summary

This RFC proposes evolving the BRAIN v2 Terminal User Interface (`brain-v2`) from a conversational query-retrieval client into an **Interactive Knowledge Exploration Environment**. 

Instead of treating the TUI as a simple text console, we define a clear separation between **Conversation Mode** (focused on prompt execution and linear timeline rendering) and **Knowledge Exploration Mode** (focused on analyzing the metadata, provenance, relationships, and context of the underlying memory graph).

Phase 1 focuses strictly on a **read-only exploration interface**. No graph editing, node annotations, pinning, or collections are supported yet. The goal is solely to help users understand why a memory exists and how it connects.

## 2. Affected Subsystems

- `crates/brain-tui`
  - `state.rs`: Navigation modes, active inspector sessions, breadcrumb vectors, and viewmodel generation.
  - `ui/renderer.rs` & `ui/widgets/`: Multi-pane layouts and inspector pane rendering.
  - `lib.rs`: Keyboard event mapping transitions between modes, traversal triggers, and scrolling.
- `crates/brain-domain` & `crates/brain-services`
  - Domain models representing the unified `InspectorModel` payload.
- `daemon` & `protocol`
  - Protocol message types for single-turn query retrieval of the complete `InspectorModel`.

## 3. Component Ownership & Responsibilities

To preserve Version 1 stability invariants, component boundaries are strictly partitioned:

| Component | Responsibility | Allowed Actions | Disallowed Actions |
|---|---|---|---|
| **Daemon** | Graph Storage & Context Resolution | Serves SQLite queries; resolves node neighbors, provenance data, and retrieval details; packages them into `InspectorModel`. | Maintains zero UI state; does not track breadcrumbs or active panels. |
| **UdsClient** | Transport Adapter | Serializes and deserializes the JSON wire frames; handles socket liveness. | Maintains zero state variables; does not cache history or sort sessions. |
| **UiState** | Controller & Reducer | Owns breadcrumb stack; recalculates scroll bounds and active panel layout; holds active inspector models; manages mode transitions. | Direct rendering to screen cells; network call blocking. |
| **Renderer** | Stateless Projector | Projects the `UiState` viewmodel to cells; draws borders, styles, and highlights. | Mutates any `UiState` parameter; changes scroll offsets; triggers network calls. |

## 4. Proposal Details

### 4.1 Mode Transitions: Conversation vs. Exploration

The TUI operates in two distinct modes, managed by the state controller:

```
                  ┌──────────────────────┐
                  │   Conversation Mode  │ <--- Focus: Editor / Sidebar
                  └──────────────────────┘
                     │                ▲
                     │ (Select link/  │ (Esc/Backspace
                     │  press Enter)  │  on empty stack)
                     v                │
                  ┌──────────────────────┐
                  │   Exploration Mode   │ <--- Focus: Inspector / Timeline
                  └──────────────────────┘
```

1. **Conversation Mode**: Standard interface optimized for typing queries and viewing streaming timeline responses. The input cursor resides in the prompt editor. Keyboard events are routed strictly to the prompt editor or sidebar.
2. **Knowledge Exploration Mode**: The prompt editor becomes inactive. The cursor is directed to the **Timeline** or **Inspector** panel. Keyboard events are routed strictly to the active inspector traversal/scrolling shortcuts.

---

### 4.2 Unified Inspector Information Model

Rather than making multiple network requests to resolve node details, neighbors, and weights, the client communicates with the daemon via a single application use case request. The daemon returns a complete `InspectorModel`:

```rust
pub struct InspectorModel {
    /// Target entity node details
    pub entity: NodeDTO,
    /// System metadata (created_at, updated_at, access_count, etc.)
    pub metadata: HashMap<String, String>,
    /// Adjacent relationships (incoming and outgoing edges)
    pub relationships: Vec<RelationshipDTO>,
    /// Provenance tracking (source file, ingestion tool, git hash, line number)
    pub provenance: ProvenanceDTO,
    /// Dedicated section explaining why this memory was retrieved (score, keyword boosts, semantic distance)
    pub retrieval_explanation: Option<RetrievalExplanationDTO>,
    /// Chronological list of recent interactions or updates
    pub recent_activity: Vec<ActivityLogEntry>,
}
```

#### 4.2.1 Inspector Loading and Error States
- **Loading State**: When a node is requested, `InspectorSession::load_state` is set to `Loading`. The Inspector pane renders a progress indicator (e.g. `⚡ Loading node details...`).
- **Error/Not Found State**: If `inspect_node()` fails due to network disconnect, or the entity no longer exists in the daemon database:
  - `InspectorSession::load_state` transitions to `Error(msg)`.
  - The Inspector pane renders a prominent warning panel: `⚠ Failed to inspect node: <Error Message>`.
  - The user can press `Backspace` to return to the previous node or `Esc` to close the Inspector cleanly.

#### 4.2.2 Caching Constraints
- **Zero Client-Side Caching**: In Phase 1, `UiState` performs **no client-side caching** of `InspectorModel` payloads. Traversing to a node, even one previously visited in the breadcrumb history, always triggers a fresh IPC query to the daemon to ensure correctness against background database consolidation.

---

### 4.3 Traversal & Breadcrumbs

- **Active Session Scoping**: The breadcrumb navigation history is owned strictly by the active `InspectorSession`. 
- **Volatile Lifespans**: When the user exits Knowledge Exploration Mode and returns to Conversation Mode, the breadcrumb stack is completely cleared.
- **Breadcrumb Navigation**:
  - Hitting `Enter` on a related entity in the Inspector queries the new node's `InspectorModel` and pushes it onto the breadcrumb history stack.
  - Hitting `Backspace` pops the last node off the history stack. If the stack becomes empty, the TUI exits Exploration Mode and returns to Conversation Mode.

## 5. Interaction Model & Responsive Layouts

### 5.1 Minimum Width Constraints
Instead of using fixed terminal column breakpoints, panel visibility is determined dynamically by summing the **minimum width requirements** of each panel:

| Panel | Minimum Width | Description |
|---|---|---|
| **Sidebar** | 20 columns | Left session listing and filters |
| **Chat Timeline** | 50 columns | Center message feed and prompt |
| **Inspector** | 35 columns | Right knowledge inspector pane |

The layout manager evaluates available columns (`W`):
- If `W >= (Sidebar_min + Chat_min + Inspector_min)` (105 columns) AND the Inspector is active: Render all three panels side-by-side.
- If `W >= (Sidebar_min + Chat_min)` (70 columns): Hide the Inspector panel; toggle the central panel view between Chat Timeline and Inspector view when switching modes.
- If `W < 70 columns`: Hide the Sidebar and Inspector. Only the Chat Timeline or full-screen Inspector is rendered.

---

### 5.2 Keybindings & Keyboard Ownership

Keyboard shortcut handlers are strictly separated based on the active mode:

#### Conversation Mode Shortcuts
- `Enter` (prompt editor): Submit prompt.
- `Tab`: Cycle focus between Editor and Sidebar.
- `Ctrl+N`: Start new conversation thread.
- `PageUp` / `PageDown`: Scroll timeline view.

#### Exploration Mode Shortcuts
- `Tab`: Cycle focus between Timeline references and Inspector panel.
- `Up` / `Down`: Navigate highlighted adjacent connections in Inspector.
- `Enter` (inspector list): Traverse/inspect highlighted neighbor node.
- `Backspace` (inspector): Return to previous node in breadcrumbs.
- `Esc` (inspector): Close Inspector and return to Conversation Mode.

---

### 5.3 Semantic Render Spans
To support interaction, we introduce **Semantic Render Spans** inside `VisualLine` instead of trying to parse raw links out of text layout spans:

```rust
pub enum VisualSpanKind {
    Normal,
    Code,
    /// Represents a traversable link reference to a graph entity
    EntityReference(NodeId),
}
```

The renderer styles `EntityReference` spans distinctly (e.g. underline/accent colors) and allows keyboard navigation to jump between them when the timeline is focused.

## 6. Capability Roadmap (Sprint C)

### Phase 1: Read-Only Exploration & Inspection (Current Scope)
- Define the unified `InspectorModel` DTOs and UDS protocol messages.
- Implement Conversation Mode vs. Knowledge Exploration Mode transition boundaries in `state.rs` and `lib.rs`.
- Implement dynamic layout management using minimum panel width constraints.
- Render Semantic Render Spans (`EntityReference`) inside the timeline.
- Implement the dedicated Inspector widget:
  - **Metadata Section**: System stats, type, and dates.
  - **Relationships Section**: List of connections.
  - **Provenance Section**: File location and source details.
  - **Retrieval Explanation**: Dedicated panel highlighting scores and boosts.
  - **Recent Activity Section**: Interactive history logs.
- Wire volatile breadcrumb navigation history.

### Phase 2: Actionable Pinning & Mutations (Future Scope)
- Add pinning actions (`Space` toggle) to attach entities to prompt context.
- Support node grouping inside local workspace "Collections".
- Support manual node annotation editing directly inside Exploration Mode.
- Support graph structural mutations (adding nodes and relationships).

## 7. Manual Acceptance Scenarios

### Scenario 1: Breadcrumb Cleanup on Close
1. Select a node in the timeline to enter **Exploration Mode** (breadcrumb stack: `[Node_A]`).
2. Highlight a related entity in the Inspector and press `Enter` to traverse (breadcrumb stack: `[Node_A, Node_B]`).
3. Press `Esc` to close the Inspector and return to **Conversation Mode**.
4. Select a node to re-enter **Exploration Mode**.
5. Verify that the breadcrumb history stack contains only the new node, confirming that the prior traversal stack was cleanly purged on close.
