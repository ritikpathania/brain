## 1. Executive Summary

Projections (defined in RFC-008) and Events (defined in RFC-009) represent the read and communication layers of the Brain runtime. To establish the final core runtime contract, this RFC defines the write and evolution model, answering the central question: **How does canonical knowledge change over time?**

Rather than treating knowledge processing as a rigid, linear sequence (or "pipeline"), this RFC defines evolution through **Transformation Boundaries**. Each boundary governs a distinct phase of data mutation, validation, and enrichment. By isolating write-state mutations strictly to a single boundary (Canonicalization), we protect the semantic graph's integrity and ensure that all downstream operations (Reflection, Projection) remain deterministic, side-effect-free, and capability-isolated.

## 3. Proposal Details: Transformation Boundaries

To prevent architectural drift and maintain strict Domain-Driven Design (DDD) invariants, all knowledge evolution is segmented into four deterministic boundaries.

### A. The Invariant Matrix

The behavior of each boundary is strictly governed by the following operational constraints:

| Boundary | Input | Output | Deterministic | Emits Domain Event | Invalidates Projections |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Observation** | Raw external input | Observation DTO | Yes | No | No |
| **Canonicalization** | Observation DTO / Command | Canonical Knowledge | Yes | Yes | Yes |
| **Reflection** | Canonical Knowledge | Derived Knowledge | Yes | Yes | Yes |
| **Projection** | Canonical Knowledge | Projection Instance | Yes | No | No |

---

### B. Detailed Boundary Responsibilities

#### 1. Ingestion / Inputs
Ingestion defines what enters the runtime. Brain is protocol-independent; therefore, inputs can arrive from diverse sources. We explicitly separate two kinds of input semantics:
*   **Observations (Information)**: External data, prompts, conversation files, or database nodes entering the system to be canonicalized into the graph.
*   **Commands (Intent)**: External instructions executing specific operations (such as deleting a node, archiving a session, or triggering a sync).
*   **Other Ingestion Sources**: Batch imports, historical event log replays, and storage migrations.

#### 2. Validation
Before raw input transitions into canonical knowledge, it must cross the validation boundary to answer: **Can this become canonical?**
We split validation into two distinct responsibilities:
*   **Structural Validation**: Can this input be parsed and deserialized successfully? Focuses on format validity and structural constraints.
*   **Semantic Validation**: Can this input safely merge into the canonical graph? Focuses on invariant validation, identity compatibility, permission boundaries, and authorization checks.
*   **Provenance**: Recording source origin, timestamp, and creator credentials. **Provenance is strictly immutable** once canonicalization successfully commits.

#### 3. Canonicalization
This is the heart of the evolution model. Information becomes canonical knowledge only during this step.
*   **CORE INVARIANT**: **Only canonicalization is permitted to mutate canonical knowledge.**
*   This boundary is responsible for:
    *   Entity normalization and deduplication.
    *   Applying strict merge rules (governing how properties are joined or overridden).
    *   Creating semantic relationships (edges) and resolving taxonomic classifications.
    *   Enforcing graph-wide semantic consistency.

#### 4. Reflection
Reflection is an **optional semantic evolution phase** that derives additional knowledge without changing the meaning of existing canonical knowledge.
*   **Enrichment Over Mutation**: Reflection cannot rewrite history, delete observations, or mutate core observations.
*   **Incremental Execution**: Reflection must operate incrementally over affected semantic sub-graphs and modified entities whenever possible, rather than scanning the entire graph.
*   All reflection outcomes are written as *Derived Knowledge*, which can be re-calculated or discarded without altering the underlying canonical facts.

#### 5. Projection Invalidation
Whenever canonical or derived knowledge changes, the runtime invalidates dependent projection instances:

```
Canonical/Derived Knowledge Mutation
                  │
                  ▼
         Emit Domain Event
                  │
                  ▼
     Trigger Projection Invalidation
                  │
                  ▼
        Stream Runtime Event
```

## 4. Core System Invariants

### A. Semantic Identity
Canonical entities retain a stable semantic identity across merges, database migrations, reflection passes, and storage evolution. While physical storage representations (such as database row keys or file layouts) may adapt, the logical identity of a semantic node remains constant.

### B. Determinism
Given identical inputs, identical starting runtime state, and identical configuration, the evolution model must guarantee that **the resulting canonical state is identical**.
*   **No Randomness**: Clustering, similarity calculations, and ID generations must utilize deterministic, seeded, or content-addressable hash functions (e.g. `uuid::v5` or `FNV-1a`).
*   **Stable Ordering**: Data arrays, graph traversals, and merge sequences must enforce deterministic sorting keys (such as sorting by entity ID or epoch timestamp) before execution.
*   **Isolated PyO3/Python Executions**: Semantic extractions running in Python plugins must be stateless and return deterministic outputs for matching inputs.

## 5. Contract Changes (Interfaces & Types)

We define the following lifecycle traits and context containers inside `crates/brain-core/src/evolution.rs`.

### Rust Crate Signature Changes

```rust
// crates/brain-core/src/evolution.rs

use serde::{Serialize, Deserialize};
use std::time::SystemTime;
use brain_domain::id::{EpochId, EntityId};
use brain_core::event::{CorrelationId, RuntimeEvent};

/// Metadata tracking where the input originated.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Provenance {
    pub source_adapter: String,
    pub timestamp: SystemTime,
    pub correlation_id: CorrelationId,
}

/// Raw observations entering the runtime.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Observation {
    pub payload: Vec<u8>,
    pub media_type: String,
    pub provenance: Provenance,
}

/// Structural validation error (formatting/deserialization).
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct StructuralValidationError {
    pub field: String,
    pub error_code: String,
}

/// Semantic validation error (graph constraints/auth).
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SemanticValidationError {
    pub entity_id: Option<EntityId>,
    pub violation: String,
}

/// Ingestion boundary interface.
pub trait IngestionValidator {
    type Error: std::error::Error + Send + Sync + 'static;

    /// Validates raw inputs structurally.
    fn validate_structure(&self, obs: &Observation) -> Result<(), Vec<StructuralValidationError>>;

    /// Validates inputs against active graph invariants and security policies.
    fn validate_semantics(&self, obs: &Observation) -> Result<(), Vec<SemanticValidationError>>;
}

/// Opaque descriptor for emitted domain events.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct DomainEventDescriptor {
    pub event_type: String,
    pub timestamp: SystemTime,
}

/// Unique reference to a target projection instance.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ProjectionInstanceId(pub String);

/// Rich feedback context returned when canonicalization completes.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CanonicalizationResult {
    /// Monotonic epoch representing the new state of the graph.
    pub epoch: EpochId,
    /// List of durable domain events committed to the store.
    pub domain_events: Vec<DomainEventDescriptor>,
    /// Entities created or mutated during this transaction.
    pub affected_entities: Vec<EntityId>,
    /// Target projection instances invalidated.
    pub invalidated_projections: Vec<ProjectionInstanceId>,
}

/// Core interface for mutating the canonical graph.
pub trait Canonicalizer {
    type Error: std::error::Error + Send + Sync + 'static;

    /// Normalizes, deduplicates, and commits the validated observation.
    /// Returns a comprehensive result payload.
    fn canonicalize(&self, obs: Observation) -> Result<CanonicalizationResult, Self::Error>;
}

/// Background reflection interface.
pub trait Reflector {
    type Error: std::error::Error + Send + Sync + 'static;

    /// Executes background reasoning or compaction.
    /// Writes derived knowledge and triggers invalidation if state updates.
    fn reflect(&self, target_epoch: EpochId) -> Result<(), Self::Error>;
}
```

## 6. Backward Compatibility Plan

*   **VCS & Event Logs**: The separation of durable Domain Events ensures that the event store remains an append-only transaction ledger. Replaying this log under deterministic rules will reconstruct identical canonical graphs.
*   **Storage Migrations**: Structural table migrations inside SQLite are managed by versioned migrations, decoupled from the memory runtime.

## 7. Verification & Testing Plan

### Automated Tests
- **Transformation Determinism Assertions**: Integration tests asserting that feeding the same observations into identical empty database states generates bit-wise identical SQLite databases.
- **Merge Collision Tests**: Mocking conflicting observations (e.g. updating an entity property concurrently) and validating that deterministic merge rules resolve conflicts identically.
- **Reflection Isolation Verification**: Asserting that executing background reflection generates derived knowledge without altering or corrupting the source canonical nodes or history logs.
