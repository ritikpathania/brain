# RFC-001: System Specification

This document defines the stable interfaces, crate boundaries, type definitions, and domain contracts for **Brain**. It serves as the canonical system specification. All implementations and migrations must conform to these definitions.

---

## 1. Crate Architecture & Directory Layout

The workspace is organized into a parent workspace containing applications, domain crates, and a Python package.

```
brain/
├── apps/
│   └── brain/                  # CLI/TUI Application executable entry point (main.rs)
├── crates/
│   ├── brain-domain/           # Pure domain entities, strongly-typed IDs, DTOs, and API models
│   ├── brain-core/             # Trait specifications, Repository interfaces, Error types
│   ├── brain-events/           # Command & Event message envelopes, Event Bus interfaces
│   ├── brain-storage/          # SQLite schema, Connection Pool, Private Repository implementations
│   ├── brain-config/           # Settings schema, loading hierarchy, precedence resolver
│   ├── brain-session/          # Session Context state machine & volatile cache
│   ├── brain-tools/            # Core system tools (filesystem, git, shell, memory, LLM)
│   ├── brain-plugins/          # Manifest parser, Lifecycle state engine, Dependency resolver
│   ├── brain-python/           # PyO3 host execution block & in-process python adapter
│   ├── brain-tui/              # Thread-isolated Ratatui user interface
│   ├── brain-services/         # Business logic services (embedding, retrieval, session)
│   └── brain-observability/    # Tracing, metrics, profiling spans, OpenTelemetry exporters
└── python/
    └── brain_ai/               # Versioned Python API client package (brain_ai.api.v1)
```

### API Stability Rules
To protect the codebase from interface erosion:
1. **`brain-domain` SemVer:** All changes to structs in `brain-domain` must undergo an RFC review. Breaking changes require major version increments.
2. **Versioned Commands & Events:** Envelopes are strictly versioned. Backward-compatibility parsers must be preserved for one major release.
3. **Python API & Plugin ABI:** Versions must be strictly checked at startup. The Python package under `brain_ai.api.v1` and Rust traits are frozen once released.

## 2. Domain Models & DTOs (`brain-domain`)

This crate contains pure data structures. They are independent of storage, network, and execution runtime layers.

### Strongly-Typed Identifiers
Standardizing ID formatting:
* `SessionId` and `RunId` use ULIDs for chronological sortability.
* `NodeId` uses UUIDs for standard unique identifier hashing.

## 3. Core Traits & Repositories (`brain-core`)

This crate defines the abstract interfaces. To maintain strict encapsulation, **repositories are private to the service layer**. Subsystems like TUI or CLI can never call repositories directly; they must interact via Service boundaries.

### Repository Interfaces
Repositories perform only atomic CRUD operations. Graph algorithms and vector similarity searches are moved to `RetrievalService` in `brain-services`.
```rust
use crate::errors::BrainError;
use brain_domain::*;

pub trait NodeRepository: Send + Sync {
    fn save(&self, node: &Node) -> Result<(), BrainError>;
    fn save_batch(&self, nodes: &[Node]) -> Result<(), BrainError>;
    fn find_by_id(&self, id: &NodeId) -> Result<Option<Node>, BrainError>;
    fn delete(&self, id: &NodeId) -> Result<(), BrainError>;
    fn list_all(&self) -> Result<Vec<Node>, BrainError>;
}

pub trait EdgeRepository: Send + Sync {
    fn save(&self, edge: &Edge) -> Result<(), BrainError>;
    fn save_batch(&self, edges: &[Edge]) -> Result<(), BrainError>;
    fn find_by_id(&self, id: &EdgeId) -> Result<Option<Edge>, BrainError>;
    fn delete(&self, id: &EdgeId) -> Result<(), BrainError>;
    fn get_connections(&self, node_id: &NodeId) -> Result<Vec<Edge>, BrainError>;
    fn decay_weights(&self, half_life_secs: f64, threshold: f64) -> Result<(), BrainError>;
}

pub trait EmbeddingRepository: Send + Sync {
    fn save(&self, embedding: &Embedding) -> Result<(), BrainError>;
    fn find_by_node_id(&self, node_id: &NodeId) -> Result<Option<Embedding>, BrainError>;
    fn delete(&self, node_id: &NodeId) -> Result<(), BrainError>;
    fn list_all_embeddings(&self) -> Result<Vec<Embedding>, BrainError>;
}

pub trait SessionRepository: Send + Sync {
    fn save_session(&self, id: &SessionId, history: &Conversation) -> Result<(), BrainError>;
    fn load_session(&self, id: &SessionId) -> Result<Option<Conversation>, BrainError>;
    fn delete_session(&self, id: &SessionId) -> Result<(), BrainError>;
}

pub trait ConfigRepository: Send + Sync {
    fn save_key(&self, key: &str, val: &str) -> Result<(), BrainError>;
    fn get_key(&self, key: &str) -> Result<Option<String>, BrainError>;
}
```

## 7. Resource & Thread Manager (`brain-runtime`)

The `ResourceManager` exposes abstracted interfaces. It hides concrete types like `rusqlite::Connection` or `reqwest::Client`.

```rust
        where F: FnMut(&rusqlite::Row<'_>) -> rusqlite::Result<T>;

pub trait HttpClient: Send + Sync {
    fn get(&self, url: &str) -> Result<String, BrainError>;
    fn post(&self, url: &str, json_body: &serde_json::Value) -> Result<String, BrainError>;

pub trait ResourceManager: Send + Sync {
    fn startup(&self) -> Result<(), BrainError>;
    fn shutdown(&self) -> Result<(), BrainError>;
    
    // Resource Handle Accessors
    fn get_storage_handle(&self) -> Result<Arc<dyn StorageHandle>, BrainError>;
    fn get_python_runtime(&self) -> Result<Arc<dyn AgentRuntime>, BrainError>;
    fn get_http_client(&self) -> Arc<dyn HttpClient>;
    
    // System Telemetry
```

### Task Scheduler Specification
Tasks return `TaskHandle` objects to allow dynamic cancellation of long-running operations.

## 8. Agent Execution Pipeline

The execution steps of an agent request are normalized into a canonical pipeline:

```
  [Receive Request] ──> [Retrieve Memory] ──> [Plan Actions] ──> [Execute Tools]
                                                                        │
  [Respond] <── [Persist Results] <── [Reason / Synthesize] <───────────┘
```

1. **Receive Request:** Extract inputs and check session permissions.
2. **Retrieve Memory:** Execute `RetrievalService` hybrid search.
3. **Plan Actions:** Query `PlannerAgent` for required tool steps.
4. **Execute Tools:** Invoke target `Tool` executions through the `ToolRegistry`.
5. **Reason / Synthesize:** Formulate final user-facing text.
6. **Persist Results:** Commit conversations and graphs to database.
7. **Respond:** Output final message stream.

## 9. Startup State Machine

Dynamic transitions are validated at runtime. Invalid transitions return a recoverable `Result::Err`, ensuring failures are reportable.

```
  [Boot] ──> [LoadConfig] ──> [InitLogging] ──> [InitStorage] ──> [RunMigrations]
                                                                        │
  [Running] <── [Ready] <── [StartRuntime] <── [LoadPlugins] <──────────┘
      │
      └──> [Shutdown]
```

## 10. Stable Python Boundary (`brain-python` & `brain_ai`)

The PyO3 bridge is strictly encapsulated inside `brain-python`. No other Rust crate can import or call `pyo3` functions.

### Versioned Python Interface (`python/brain_ai/api/v1/__init__.py`)
Python endpoints utilize structured Pydantic models (data classes) instead of dictionaries.
```python
from abc import ABC, abstractmethod
from typing import List, Optional
from pydantic import BaseModel, Field

class ModelRequest(BaseModel):
    prompt: str
    system_instructions: Optional[str] = None

class ModelResponse(BaseModel):
    text: str
    token_count: int

class MemoryResult(BaseModel):
    node_id: str
    label: str
    node_type: str
    properties: dict = Field(default_factory=dict)
    score: float

class PythonAgent(ABC):
    @abstractmethod
    def name(self) -> str:
        pass
    
    @abstractmethod
    def run(self, context: 'AgentContext', conversation: List[dict]) -> str:
        pass

class AgentContext(ABC):
    @abstractmethod
    def invoke_model(self, request: ModelRequest) -> ModelResponse:
        pass
    
    @abstractmethod
    def retrieve_memory(self, query: str) -> List[MemoryResult]:
        pass
    
    @abstractmethod
    def store_memory(self, node: MemoryResult) -> None:
        pass
```

## 11. Testing Contract

Every crate in the workspace must declare its participation in the test pyramid in its local `README.md`.

* **Unit Tests:** Verify atomic functions and individual code blocks locally in each crate.
* **Property Tests:** Execute fuzzing and randomized inputs (e.g., STM inverted index searching).
* **Integration Tests:** Verify multi-crate workflows, SQLite repository queries, and service layer coordinator logic.
* **Snapshot Tests:** Enforce terminal viewport rendering consistency and UI layout correctness.
* **End-to-End Tests:** Verify full-pipeline agent execution and IPC message routing.
* **Benchmark Tests:** Profile execution latency, memory footprint, and prevent regressions.
