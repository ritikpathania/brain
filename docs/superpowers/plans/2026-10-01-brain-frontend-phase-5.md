## 2. Build, identity, manifests, and source fingerprint

### 2.1 Fixed build command and output

Add package script `"build": "bun run scripts/build.ts"`; keep all existing scripts unchanged. Extend `tsconfig.json` include to `scripts/**/*.ts`. The original no-JS-dependency/lockfile-change assumption is superseded only by the approved Task 1 amendment below.

`scripts/build.ts` uses argument-based spawning of its verified Bun executable, with the package root resolved from `import.meta.url`. Reject a Bun version other than **1.4.4** and a requested non-native target. Supported mappings:

| Rust target | Bun target | Runner |
| --- | --- | --- |
| `aarch64-apple-darwin` | `bun-darwin-arm64` | native macOS arm64 |
| `x86_64-unknown-linux-gnu` | `bun-linux-x64` | native Linux x86_64/glibc |

The concrete build argument vector is equivalent to:

```bash
bun build src/cli/main.ts --no-env-file --compile --production --minify --sourcemap=none \
  --target=<native-Bun-target> --outfile=dist/brain-frontend/brain-frontend \
  --no-compile-autoload-dotenv --no-compile-autoload-bunfig \
  --no-compile-autoload-tsconfig --no-compile-autoload-package-json \
  --reject-unresolved --define '__BRAIN_COMPILED_IDENTITY__=<literal JSON>'
```

The placeholder denotes one argv element containing `JSON.stringify(identity)`, not shell expansion/evaluation. Strip `BUN_BE_BUN`, `BUN_OPTIONS`, and `NODE_OPTIONS` from the build subprocess; `--no-env-file` disables build-time dotenv loading. Local/release orchestrators also launch the initial build tool with a temporary HOME and `--no-env-file --config=/dev/null`, so a preload cannot execute before `build.ts` sanitizes its child. Expose build-tool-only `--target <Rust-triple>` and `--output <artifact-directory>` arguments; default target must agree with Bun's native OS/architecture and `rustc -vV` host, and default output is the package's `dist/brain-frontend`. Stage builds under an owned temporary output, publish the verified pair only on success, and allow replacing only a previously validated owned pair; refuse overwriting an unrelated/nonempty output. Thus `bun run build` is repeatable without an arbitrary recursive deletion. No bytecode/PGO, source maps, splitting, external application packages, or performance work. Audit required unresolved imports/assets if build fails; do not fabricate modules or change presentation to suppress a build defect. These flags are verified in local 1.4.4 help and the [official standalone documentation](https://bun.com/docs/bundler/executables).

Outputs: `dist/brain-frontend/brain-frontend` and `dist/brain-frontend/manifest.json`. Optional build module metadata stays outside the shipped pair. macOS signing, if needed, happens **before** final executable hashing. Use native `file`/loader inspection; do not infer platform solely from its filename. Existing `.gitignore` already ignores `dist/` and `node_modules/`.

### 2.2 Exact source-input fingerprint algorithm

Implement `collectSourceIdentity(repositoryRoot: string): SourceIdentity` in `packages/brain-frontend/scripts/release/sourceIdentity.ts`. It accepts only a real Brain Git root; commands use argv and NUL-delimited output. Define `SourceIdentity = { sha: string; dirty: boolean; fingerprint_algorithm: 'brain-source-tree-v1'; fingerprint_sha256: string; untracked_input_count: number }`.

1. Read root and full SHA with `git rev-parse --show-toplevel` and `git rev-parse --verify HEAD`. Obtain paths from the union of `git ls-tree -r -z --name-only HEAD`, `git ls-files --cached -z`, and `git ls-files --others --exclude-standard -z`. Inspect `git status --porcelain=v1 -z --untracked-files=all` separately for dirty state.
2. Restrict fingerprint inputs to these explicit product/build/verification scopes: root `Cargo.toml`, `Cargo.lock`, `LICENSE`, `.gitignore`, `package.sh`, and any existing `rust-toolchain` / `rust-toolchain.toml`; directory prefixes `.cargo/`, `.github/workflows/`, `apps/`, `crates/`, `daemon/`, `xtask/`, `generated/`, `sdks/`, `packages/brain-frontend/`, `scripts/release/`; exact scripts `scripts/package-daemon-runtime.sh`, `scripts/verify-daemon-runtime.sh`, `scripts/package-brain-product.sh`, `scripts/verify-frontend-artifact.sh`, `scripts/verify-brain-product.sh`. Within scope include tracked files (even if newly ignored), staged additions, and non-ignored untracked files. Hash **current working-file bytes**, not patch/index bytes. Staged versus unstaged placement does not affect the fingerprint. Missing/deleted paths contribute no current-tree record; their Git status still makes the tree dirty. An untracked replacement at a formerly tracked path contributes once. Documentation/evidence and the legacy shell are not build inputs and are not hashed; recording final archive digests therefore cannot create a fingerprint self-reference. Required inputs outside scope must be rejected or added by explicit plan review, not silently left unhashed.
3. Exclude generated/output components by exact path component: `.git`, `target`, `node_modules`, `dist`, `.venv`, `__pycache__`, `.pytest_cache`, `.ruff_cache`, `.ty_cache`, `.mypy_cache`, `.code-review-graph`; also root `artifacts/` and `release_assets/`, and root packaging archives/checksum outputs. Do not exclude all `generated/`: checked-in generated contracts are inputs. A **tracked** file in an excluded output location is an error requiring review, not silently omitted. Ignored untracked files are excluded; required source/build/license inputs hidden by ignore rules are a build error.
4. Convert relative paths to POSIX `/`, reject absolute/escaping paths and non-UTF-8 path names, preserve case and Unicode byte representation (no case-folding, NFC, or line-ending conversion), deduplicate, and sort by unsigned UTF-8 path bytes. Reject Git submodules and special filesystem nodes in this input set rather than hashing them ambiguously. Resolve parent-directory symlinks within the repository; never read a file through an escaping parent.
5. For regular files use Git-normalized mode `100755` if any executable bit is set, else `100644`, and SHA-256 of exact bytes. For a symlink use mode `120000`, kind `symlink`, and SHA-256 of its raw link-target UTF-8 bytes without dereferencing it; reject absolute/escaping links used as build inputs. Empty directories, ownership, timestamps, permissions other than executable bit, Git branch, Git status ordering, and absolute root are not hashed.
6. Hash UTF-8 prefix `brain-source-tree-v1\n`, then each sorted record as `path + NUL + kind + NUL + mode + NUL + lowercase-content-sha256 + LF`. File kind is `file` or `symlink`. The result is `fingerprint_sha256`; SHA/dirty/count are **outside** this digest. Consequently equivalent source trees in different directories, or staged differently, have the same fingerprint.
7. `dirty` reports any non-generated tracked/index change or non-ignored untracked file across the repository (including docs), while `untracked_input_count` counts only included fingerprint inputs. Generated status entries are removed by the same exclusions. Thus dirty metadata can differ between equivalent trees without changing their content fingerprint. Capture identity before and after build and again before assembly; reject changed SHA/fingerprint/dirty metadata or input count. Serialize manifest JSON with deterministic key order, indentation and one LF; no timestamp, absolute root, or random staging path.

The ignore-rule rejection concerns **owned** source/build/license inputs. Installed dependencies and interpreters in ignored `node_modules`/`.venv` are derived toolchain inputs: validate their locked install/version/integrity separately, and record shipped runtime hashes rather than putting host installation paths in this fingerprint.

Tests use disposable Git repositories, including staged/unstaged equivalents, deleted/replaced files, untracked source, ignored output, tracked ignored input, symlink/mode changes, shuffled path discovery, spaces/non-ASCII names, different roots, documentation-only edits, and mid-build mutation. CI publication additionally requires clean Git status and all mandatory owned source/scripts/notices committed; local dirty artifacts remain explicitly non-release evidence. Evidence updates must precede the final rebuild/check, or preserve identical recorded dirty metadata; do not alter input files after their last verification.

Artifacts built in an early task are test outputs, not final release evidence after later source/script/workflow changes. After Tasks 7–8's edits, rebuild CLI/daemon and the standalone frontend from the same final snapshot, assemble a fresh product, then rerun archive/extraction checks. Never reuse an old F merely because its executable still starts.

### 2.3 Compiled identity and frontend schema

`src/cli/buildIdentity.ts` defines immutable `BuildIdentity` and `readCompiledIdentity(): BuildIdentity | null`. The build substitutes the reserved constant; it is never resolved from environment, neighboring JSON, CWD, or command-line identity flags. Source launch returns `null`. `--build-identity` outputs one JSON object and exits zero **before** socket resolution/bootstrap/UI imports for compiled builds; source-only use fails actionably without starting UI. Extend the existing `resolveFrontendConfiguration(argumentsList, environment = process.env, compiledIdentity = readCompiledIdentity()): FrontendConfiguration` seam: compiled mode fixes version/build ID from the constant while retaining explicit socket resolution; null preserves development behavior. Environment and CLI identity overrides are ignored in compiled mode and tested as such.

Exact compiled fields: `schema_version: 1`, `identity: 'brain-frontend'`, `package: '@brain/frontend'`, `frontend_version`, `brain_version`, `source: SourceIdentity`, `target_triple`, `runtime_model: 'bun-standalone'`, `bun_version: '1.4.4'`, `lockfile_sha256`. Versions come from package.json and workspace Cargo package metadata; Git/fingerprint comes from the algorithm above; target from the native mapping; lockfile digest from exact `bun.lock` bytes. No caller-supplied SHA/version substitution. Production handshake uses compiled frontend version and `frontendBuildId = source.fingerprint_sha256`; development overrides remain unchanged.

Frontend `manifest.json` contains these same fields plus `entrypoint: 'brain-frontend'` and `executable_sha256`. Paths are relative to **that manifest's directory**. Validation requires schema/constants, valid SemVer versions, lowercase 40-hex SHA and 64-hex digests, correct fingerprint algorithm and boolean/count types, native target, exact Brain CLI product version, executable permission, fixed basename, containment and digest. Reject unknown fields in schema-1 F/M rather than silently accepting a second identity/path field. Compare every compiled field against diagnostic JSON; do not compare a subset or let env spoof it.

### 2.4 Acyclic hash graph and product schema

```text
frontend executable --SHA256--> frontend/brain-frontend/manifest.json (F)
daemon executable + libpython --SHA256--> runtime-manifest.json (D)
all Python files/link targets --> runtime/python-files.json (P)
CLI + F + D + P + license files --SHA256--> product-manifest.json (M)
complete archive including M --SHA256--> external .tar.gz.sha256
```

Keep the existing D/P schema unchanged. D names P but does not currently digest P; **M hashes P directly**, closing that edge without a daemon schema change. F hashes only its executable. M hashes CLI and the exact bytes of both component manifests, P, and every delivered license file. Component verifiers recursively check executable/runtime leaf hashes. No manifest hashes itself. M may list its own path as shipped content, but has no self-hash or self-size. Archive digest is produced only after archive creation and is never stored inside M or the archive.

Exact M fields:

| Field | Value/meaning |
| --- | --- |
| `schema_version`, `artifact` | `1`, `brain-product` |
| `brain_version`, `source`, `target_triple` | Same product version/source identity/target as F; D's version/source SHA/target must agree. D's older dirty/count metadata is recorded as component metadata, not substituted for the source fingerprint. |
| `cli` | `{path: 'bin/brain', sha256: <digest>}` |
| `frontend` | `{manifest: 'frontend/brain-frontend/manifest.json', sha256: <F digest>}` |
| `daemon` | `{manifest: 'runtime-manifest.json', sha256: <D digest>}` |
| `python_files` | `{manifest: 'runtime/python-files.json', sha256: <P digest>}` |
| `licenses` | Sorted array of `{path: 'licenses/<file>', sha256: <digest>}`; includes the notice inventory itself. |
| `build_tools` | Exact `rustc`, `cargo`, Bun, build Python versions; no executable-home paths. |
| `contents` | Sorted root-relative file/link paths for the entire delivery, including M; no hash/size of M. Directory entries are derived. Leaf hashes are delegated to F/D/P or `licenses`/`cli`, not duplicated. |

All M paths are fixed product-root-relative paths or validated contents paths. Reject absolute paths, `..`, duplicate/case-colliding delivery paths, escaping symlinks, unexpected files, or inventory omissions. F's entrypoint has its narrower manifest-directory-relative semantics; P entries remain relative to `runtime/python`. Component/version/target mismatches fail, not warn. Frontend **0.1.0** need not equal Brain **1.1.0**, but F and compiled frontend identity must agree; CLI/daemon/M Brain versions must be equal. Digests are integrity checks, not signatures/authentication.
