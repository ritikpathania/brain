# ADR-003: Deletion of DuckDB OLAP Engine

## Context
The previous system maintained a shadow DuckDB OLAP database in addition to the SQLite OLTP transactional database. An out-of-band background sync worker copied tables row-by-row inside database locks to run 5 simple analytical queries (node counts, type distribution, degree centrality, shared neighbor similarity, latency percentiles).

This added binary bloat (DuckDB C++ linking), data drift, locks contention, and sync complexity. Furthermore, the live sync code was never executed in the production running loop.

## Decision
Remove the DuckDB OLAP engine entirely. SQLite is fully capable of calculating the basic analytical queries using indexed point queries and window functions in under 5ms, avoiding OLTP lockups. 

If future requirements mandate deep benchmark histories, token-cost analysis across thousands of runs, or evaluation dashboards, SQLite will remain the single source of truth, and DuckDB can be reintroduced as a read-only offline parquet exporting tool rather than a live-sync inline database.

## Consequences
- **Binary Size:** Decreased by ~15MB.
- **Resource Usage:** Reduced lock contention and CPU sync loops.
- **Simplification:** SQLite remains the sole transactional and analytical engine for the local companion database.
